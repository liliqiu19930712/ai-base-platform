## 1 项目概述

### 1.1 项目背景

团队规划建设十大类智能体阵列（科创、文化、教育、健康、企业、数据、知产、法律、国际知产、跨境数字贸易，合计约 **180** 个智能体）。若每个智能体各自实现登录鉴权、模型调用、向量知识库、权限、计费、审计等通用能力，将导致重复建设、标准不一、安全与审计不可控。

因此建设统一 **智能体基座平台**，实现关注点分离：

- **基座**：沉淀通用底层技术能力，一次建设，全部子平台复用。
- **子平台**：聚焦领域业务、行业知识库内容、业务交互页面与业务合规判定。

### 1.2 项目目标

| 编号 | 目标 | 度量建议 |
|------|------|----------|
| G1 | 支撑十大类智能体子平台接入，实现多租户资源与数据隔离 | 租户间数据越权访问用例通过率 100% |
| G2 | 提供统一身份、模型网关、知识库、工作流、插件、配额计费、合规审计能力 | 六大能力模块均有可调用 API 与验收用例 |
| G3 | 提供可复用公共 UI / 样板子平台，降低子平台接入成本 | 样板工程 1 日内完成联调闭环 |
| G4 | 基座版本与上层智能体季度迭代节奏对齐 | 每季度交付版本说明 + 兼容性说明 |
| G5 | 从 Demo 走向可运营、可审计、可灰度的工程化平台 | 灰度/A-B 对工作流或 Prompt 真正生效并可统计 |

### 1.3 项目范围

#### 1.3.1 范围内（In Scope）

- 身份与访问管理（账号、租户、RBAC、SSO）
- 智能体实例登记与模型网关（路由、限流、配额、计费记账、调用审计）
- 知识库底座（上传、切分、向量化、检索、版本快照、重索引）
- 提示词版本与工作流编排引擎（含可视化编排器）
- 插件注册与调度框架
- 运营能力：调用统计、灰度、A/B、合规弹窗框架、脱敏模板、会话存储框架
- 平台级租户开通与功能开关
- 公共前端组件与文化子平台样板工程

#### 1.3.2 范围外（Out of Scope）

- 任何领域业务逻辑（家谱、专利、学科教学、企业诊断、文化内容创作策略等）
- 领域知识库业务语料的采集、标注、审核与内容维护
- 子平台业务页面与业务集市卡片
- 业务侧合规判定结论（健康/法律/跨境等）
- 真实支付渠道对接（可作为后续扩展；本期以记账与配额熔断为主）
- 移动端原生 App（本期以 Web / H5 接入为主）

### 1.4 术语与缩写

| 术语 | 说明 |
|------|------|
| 基座平台 | 公共底层底座，本系统 |
| 子平台 | 十大类领域智能体平台（教育、文化、企业等） |
| 租户（Tenant） | 每一个子平台（或独立运营单元）对应一个租户，资源与数据隔离 |
| 智能体实例（Agent） | 租户内登记的单个 Agent，如「语文霸」「文化问答 Agent」 |
| IAM | 身份与访问管理 |
| RBAC | 基于角色的访问控制 |
| SSO | 单点登录；基座签发票据，子平台兑换会话 |
| RAG | 检索增强生成：向量检索片段后再调用大模型 |
| DSL | 工作流领域特定语言（JSON 描述节点与边） |
| 灰度 | 按用户稳定哈希将部分流量切到新目标（Prompt/工作流） |
| A/B 实验 | 对照组 / 实验组分流并记录指标 |
| 季度迭代 | 每 3 个月一个版本：设计月 → 迭代月 → 开发测试上线月 |
| P0 / P1 / P2 | 需求优先级：必须 / 应该 / 可以 |

### 1.5 文档约定

- **Shall / 必须**：强制需求，验收不通过则不可发布。
- **Should / 应该**：强烈建议，可延期但需登记风险。
- **May / 可以**：可选增强。
- **实现状态**见第 16 章：`已实现` / `部分实现` / `规划中`。

## 2 总体架构设计

严格遵循团队规划四层架构：自下而上为 **基础设施层 → 数据层 → 能力层 → 应用层（子平台）**。

```
┌─────────────────────────────────────────────────────────────┐
│ 应用层（子平台负责）                                          │
│  文化 / 教育 / 企业 / … 业务页 · 领域知识内容 · 业务合规判定     │
│  通过 HTTP API + 公共组件 / SSO 接入基座                       │
└────────────────────────────▲────────────────────────────────┘
                             │ API / SSO / 组件
┌────────────────────────────┴────────────────────────────────┐
│ 能力层（基座核心）                                            │
│  IAM · 网关 · 知识库 · 工作流/Prompt · 插件 · 配额 · 合规运营   │
└────────────────────────────▲────────────────────────────────┘
                             │
┌────────────────────────────┴────────────────────────────────┐
│ 数据层（基座负责存储与治理能力，内容由子平台管理）               │
│  账号/租户/权限 · 向量索引 · 会话/审计 · 灰度/A-B 配置          │
└────────────────────────────▲────────────────────────────────┘
                             │
┌────────────────────────────┴────────────────────────────────┐
│ 基础设施层（基座负责封装）                                     │
│  模型接入 · 对象存储 · 数据库 · 网络安全与访问控制               │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 基础设施层（基座负责）

基座应当封装算力与模型服务接入、对象存储、数据库；提供基础安全（网络、传输加密、访问控制、存储安全）。**上层业务不得直接对接底层模型与原始存储**，一律经基座封装。

| 能力 | 本期要求 | 后续增强 |
|------|----------|----------|
| 模型接入 | 可配置多模型后端；支持 Mock 与真实 HTTP 转发 | 统一适配 OpenAI / 国产大模型协议 |
| 数据库 | 支持关系型持久化；开发可用 SQLite，生产应支持 PostgreSQL | 读写分离、备份策略 |
| 向量存储 | 本期允许「嵌入向量落库 + 应用层相似度」 | pgvector / Milvus 等专用引擎 |
| 对象存储 | 文档元数据入库；大文件可先本地/对象存储抽象 | OSS/S3 正式对接 |

### 2.2 数据层（基座负责）

只提供存储、向量索引、数据治理能力；**领域业务数据内容由子平台管理**。主要包括：

- 用户账号、租户配置、配额与记账数据
- 知识库仓库、文档、分块、嵌入向量、版本快照
- 会话日志、模型/插件调用审计、操作留痕
- 权限策略、灰度配置、A/B 实验与事件

### 2.3 能力层（基座核心模块）

| 模块 | 职责摘要 |
|------|----------|
| IAM | 登录、租户、RBAC、SSO、企业微信 OAuth |
| 交易与配额 | Token 配额、熔断、消耗统计、订单框架 |
| 智能体网关 | 多模型路由、限流、审计、统一错误码 |
| 知识库服务 | 上传切分、向量化、检索、快照、重索引 |
| 工作流与 Prompt | 版本管理、DSL 执行、可视化编排、灰度/A-B 路由 |
| 插件框架 | 注册、调度、超时、调用日志 |
| 运营与合规 | 统计、灰度、A/B、脱敏、免责弹窗框架、会话 |

### 2.4 应用层（子平台，基座不开发业务）

十大类智能体子平台 Web/移动端；领域知识库业务内容、业务页面、业务提示词、行业业务逻辑；业务 UI 卡片。

交互模式：

1. 子平台后端/前端调用基座 REST API（携带 Token + 租户标识）。
2. 前端复用基座公共 UI 组件或参考样板工程（如 `/culture`）。
3. 跨系统登录通过 SSO 票据或企业微信 OAuth。

### 2.5 逻辑部署视图（参考）

| 环境 | 用途 |
|------|------|
| 开发环境 | 本地/内网开发，可 SQLite |
| 联调测试环境 | 子平台联调、样板验证 |
| 正式环境 | 生产；PostgreSQL + 对象存储 + 监控告警 |

## 3 职责边界（强制约束，所有子平台周知）

### 3.1 基座负责

1. 统一注册、登录、SSO、RBAC；控制谁可访问哪个租户、哪些智能体与资源。
2. 智能体网关：模型路由、调用配额、限流、全链路调用日志审计。
3. 知识库底层：向量化、索引管理、文档上传/切分/检索能力。
4. 工作流编排、提示词版本管理底层框架与可视化编排器。
5. 插件底层调度；子平台注册业务插件，基座负责执行调度。
6. 配额、调用统计、订单/会员框架（支付可选）。
7. 公共 UI 组件与样板接入工程。
8. 多租户隔离：配置、配额、知识库、审计日志按租户隔离。
9. 通用安全框架：脱敏模板、操作留痕、灰度、A/B。

### 3.2 基座绝对不负责

1. **不实现**任何领域业务逻辑。
2. **不维护**领域知识库内容（二十五史、专利库、学科题库等由子平台导入管理）。
3. **不实现**子平台业务页面与业务集市卡片。
4. **不做**业务合规判定；只提供脱敏、日志、免责弹窗框架，文案与业务规则由子平台传入。

### 3.3 冲突处理原则

若子平台提出需求落入 3.2，基座产品/架构必须退回；仅当需求可抽象为「跨子平台可复用的公共能力」时，经评审进入基座 backlog。

## 4 干系人与用户角色

### 4.1 干系人

| 干系人 | 关注点 |
|--------|--------|
| 基座模块组 | 能力完整性、兼容性、稳定性 |
| 子平台研发 | 接入成本、接口清晰、样板可抄 |
| 子平台产品 | 能力边界、上线节奏 |
| 平台管理员 | 开租户、配额、全局监控 |
| 安全/合规 | 审计、脱敏、越权防护 |
| 测试 | 可验收、可回归 |

### 4.2 系统角色

| 角色 | 说明 | 典型权限 |
|------|------|----------|
| 平台管理员 | 跨租户运营 | 租户开通/停用、平台配置 |

| 访客 | 只读或受限 | 按租户策略（可选） |

## 5 模块功能需求

> 优先级：**P0** 必须（当前季度可运营闭环）、**P1** 应该（工程化增强）、**P2** 可以（中长期）。

### 5.1 身份与访问管理（IAM）

| ID | 需求 | 优先级 | 验收要点 |
|----|------|--------|----------|
| IAM-01 | 支持账号密码登录，返回访问令牌 | P0 | 错误密码不可登录；成功返回 token |
| IAM-02 | 登录时可选择用户有权限的租户；租户列表动态来自后端 | P0 | 新建租户出现在可选列表 |
| IAM-03 | 所有受保护 API 必须校验 Token；并校验租户上下文 | P0 | 无 Token / 错租户返回明确错误码 |
| IAM-04 | RBAC：角色绑定权限键；接口级鉴权 | P0 | 无权限操作被拒绝并审计 |
| IAM-05 | 用户-租户多对多；同一用户可加入多租户 | P0 | 切换租户后数据隔离正确 |
| IAM-06 | SSO 票据：基座签发一次性短时票据，子平台兑换 Token | P0 | 票据只能用一次；过期失效 |
| IAM-07 | 企业微信 OAuth：可配置 CorpId/Secret；未配置时提供 Mock 联调 | P1 | Mock 可完成登录闭环 |
| IAM-08 | 权限/角色变更写审计日志 | P0 | 可查询到变更记录 |
| IAM-09 | 支持登出与前端会话清理，避免账号串用 | P0 | 退出后本地会话不可继续调用 |
| IAM-10 | 平台管理员与租户管理员权限分离 | P0 | 租户管理员不可开其他租户 |

### 5.2 租户开通与平台管理

| ID | 需求 | 优先级 | 验收要点 |
|----|------|--------|----------|
| TEN-01 | 平台管理员可创建租户（名称、描述、功能开关、默认配额） | P0 | 创建后可登录该租户 |
| TEN-02 | 创建租户时可同时创建租户管理员账号 | P0 | 管理员可登录并具备租户管理权限 |
| TEN-03 | 可为租户开关：网关/知识库/工作流/插件 | P0 | 关闭后对应 API 拒绝 |
| TEN-04 | 可为租户智能体配置/调整配额 | P0 | 超额熔断生效 |
| TEN-05 | 租户停用后不可再调用业务 API | P1 | 返回租户停用错误码 |

### 5.3 智能体登记与模型网关

| ID | 需求 | 优先级 | 验收要点 |
|----|------|--------|----------|
| GW-01 | 租户内必须先登记智能体实例，方可经网关调用 | P0 | 未登记返回 `AGENT_NOT_REGISTERED` |
| GW-02 | 同一 `agent_id` 可在不同租户各自存在，互不影响 | P0 | 跨租户不可共用对方登记 |
| GW-03 | `POST /gateway/chat/completions` 统一入口；禁止子平台直连模型 | P0 | 绕过无合法入口 |
| GW-04 | 支持指定模型或使用智能体默认模型 | P0 | 切换模型配置后无需改子平台代码 |
| GW-05 | 记录调用审计：租户、智能体、用户、摘要、token、费用、状态、时间 | P0 | 列表可按租户查询 |
| GW-06 | 配额校验与熔断；超额返回明确错误码 | P0 | 到达上限后拦截 |
| GW-07 | 租户/智能体级限流 | P1 | 超限返回限流错误 |
| GW-08 | 流式响应（SSE/chunk） | P1 | 客户端可增量接收 |
| GW-09 | 调用统计：次数、token、费用、错误率 | P0 | 控制台/API 可查看 |
| GW-10 | 统一错误封装（见 7.3） | P0 | 错误码稳定可文档化 |

### 5.4 交易与计费配额

| ID | 需求 | 优先级 | 验收要点 |
|----|------|--------|----------|
| QUO-01 | 按租户+智能体设置 token 配额（月/日周期字段可配置） | P0 | 查询可见 limit/used |
| QUO-02 | 每次成功调用累加 used，并计算 cost（按模型单价） | P0 | 与审计日志一致 |
| QUO-03 | 订单/会员订阅数据模型与记账框架 | P2 | 可记录订单，支付可后置 |
| QUO-04 | 配额重置任务（按周期） | P1 | 周期到后 used 清零或滚动 |

### 5.5 统一知识库服务

| ID | 需求 | 优先级 | 验收要点 |
|----|------|--------|----------|
| KB-01 | 创建知识库仓库，归属租户 | P0 | 他租户不可见 |
| KB-02 | 文档上传、自动切分、向量化入库 | P0 | 上传返回 chunk_count、vectorized |
| KB-03 | 向量检索：query → topN 片段 + 相似度分数 | P0 | 语义相关文档排序靠前 |
| KB-04 | 标签过滤检索 | P1 | tags 过滤生效 |
| KB-05 | 文档列表、删除（逻辑删） | P0 | 删除后不可被检索 |
| KB-06 | 版本快照 | P0 | 可创建快照并查询历史 |
| KB-07 | 快照回滚 | P1 | 回滚后检索内容符合快照 |
| KB-08 | 重索引（全库重建嵌入） | P0 | reindex 后仍可检索 |
| KB-09 | 嵌入实现可替换（本地哈希 / 外部 Embedding / pgvector） | P1 | 接口不变，实现可插拔 |

**向量方案要求（本期）：**

- 必须提供可用的向量检索闭环，不依赖外网模型亦可演示。
- 嵌入维度、相似度算法需在版本说明中写明。
- 生产应支持迁移到专用向量引擎，且 **检索 API 契约保持兼容**。

## 6 关键用例与端到端流程

### 6.1 UC-01 租户开通

**参与者**：平台管理员  

**主成功场景**：

1. 管理员登录 `/admin`。
2. 填写租户名称、功能开关、默认配额、租户管理员账号。
3. 系统创建租户、功能配置、管理员用户与角色绑定、可选默认智能体配额。
4. 租户管理员使用新账号登录控制台。

**验收**：新租户出现在登录租户列表；管理员可调用已开启能力。

### 6.2 UC-02 智能体调用闭环

1. 租户登记智能体。  
2. 用户登录并选择租户。  
3. 调用网关对话。  
4. 系统校验登记 → 限流 → 配额 → 转发模型 → 记账 → 写审计。  
5. 返回统一结构（内容 + usage + billing）。

### 6.3 UC-03 知识库 RAG

1. 创建知识库 → 上传文档 → 自动切分向量化。  
2. 检索得到带 score 的片段。  
3. （可选）工作流 `retrieve → llm` 生成回答。

### 6.4 UC-04 子平台 SSO 进入

1. 用户已在基座登录。  
2. 子平台请求 `POST /auth/sso/ticket`。  
3. 跳转子平台并 `POST /auth/sso/exchange`。  
4. 子平台持 Token 调用网关/知识库。

### 6.5 UC-05 灰度 / A-B 生效

1. 配置 A/B（或灰度）。  
2. 用户请求 resolve 或运行工作流。  
3. 系统按稳定哈希选择 control/treatment 或灰度目标。  
4. 记录 A/B 事件，可查 stats。

### 6.6 推荐业务演示路径（验收演示脚本）

> 平台开租户 → 租户用户登录 → 登记智能体 → 建知识库并向量化 → 编排「检索+LLM」工作流 → 配置 A/B → 文化子平台用 SSO 进入问答/检索

## 9 工作流 DSL 规范

### 9.1 顶层结构

```json
{
  "name": "文化RAG编排",
  "steps": [
    {"id": "r1", "type": "retrieve", "top_n": 3},
    {"id": "p1", "type": "prompt", "prompt_id": "prompt_xxx"},
    {"id": "l1", "type": "llm", "model_id": "mock-gpt", "context_from": "r1"},
    {"id": "t1", "type": "plugin", "plugin_id": "plugin_xxx"}
  ]
}
```

### 9.2 节点类型

| type | 含义 | 关键字段 |
|------|------|----------|
| retrieve | 知识库检索 | `top_n`；运行输入需 `repo_id`+`query` |
| prompt | 套用提示词模板 | `prompt_id` 或内联 `content` |
| llm | 大模型调用 | `model_id`, `context_from` |
| plugin | 调用已注册插件 | `plugin_id`, `params` |

### 9.3 运行输入

```json
{
  "wf_id": "wf_xxx",
  "input": {
    "repo_id": "kb_xxx",
    "query": "昆曲与京剧区别",
    "variables": {}
  }
}
```

### 9.4 运行输出要求

- 必须返回逐步 `traces`（节点 id、类型、摘要、耗时/状态）。
- 若命中 A/B 或灰度，应在结果中体现 `routing` 信息（实验 id、variant、selected_id）。

### 9.5 可视化编排器要求

- 支持添加/删除/选中节点并编辑属性。
- 画布状态与 DSL 双向同步。
- 一键保存到基座、一键试运行。

## 11 安全与合规需求

1. **传输安全**：生产全站 HTTPS。  
2. **密码**：不可逆哈希存储；禁止日志打印明文密码。  
3. **密钥**：模型 API Key 等不得下发到前端明文。  
4. **租户隔离**：所有查询必须带租户条件；自动化测试覆盖越权用例。  
5. **SSO 票据**：短时、一次性、可追溯。  
6. **脱敏**：提供手机/身份证/邮箱等模板；业务规则由子平台决定何时调用。  
7. **免责声明**：基座提供弹窗框架与租户文案配置；不承担业务合规结论责任。  
8. **审计防篡改**：至少逻辑不可删；生产可考虑 WORM/只追加存储。  
9. **插件出站**：防 SSRF；超时与错误隔离。

## 12 基座接入规范（面向各子平台开发团队）

### 12.1 接入前提

1. 向基座申请并获得唯一 `tenant_id`。  
2. 明确需要的能力开关：网关 / 知识库 / 工作流 / 插件。  
3. 优先参考样板：教育/企业种子数据，以及 **文化子平台样板** `/culture`。

### 12.2 接入步骤

1. 平台侧注册租户，创建租户管理员，配置配额与功能开关。  
2. 前端引入登录/会话方式（复用组件或自建页调用登录 API）。  
3. 后端所有基座请求携带 `Authorization` 与 `X-Tenant-Id`。  
4. 登记本租户智能体；创建知识库、Prompt、工作流、业务插件。  
5. 联调：权限、网关、检索、配额熔断、SSO。  
6. 通过样板验收后进入季度版本节奏。

### 12.3 禁止行为

1. 禁止绕过基座直接调用底层大模型。  
2. 禁止跨租户访问其他子平台知识库与配置。  
3. 禁止把领域业务逻辑下沉到基座仓库。  
4. 禁止在客户端存储长期明文密钥。  

### 12.4 子平台最小集成清单

- [ ] 登录或 SSO 成功  
- [ ] 智能体已登记且网关调用成功  
- [ ]（如需要）知识库上传与检索成功  
- [ ]（如需要）工作流试跑成功  
- [ ] 配额查询与超额错误可处理  
- [ ] 合规文案可展示

## 15 风险、约束与假设

| 风险 | 影响 | 缓解 |
|------|------|------|
| 业务合规风险 | 法律/健康等误判责任不清 | 合同与 SRS 明确基座不承担业务合规结论 |
| 需求膨胀 | 基座变为业务堆砌 | 强制 3.2 边界 + 需求评审 |
| 版本兼容 | 子平台改造成本高 | 废弃窗口期 + 样板先行 |
| 模型供应商变更 | 网关适配成本 | 统一协议适配层 |
| 向量规模增长 | 检索变慢 | 迁移 pgvector/Milvus，API 不变 |
| 资源成本 | 180 智能体并发 | 配额、限流、扩容预案 |
| 插件 SSRF | 内网探测 | 白名单与出站代理 |

**假设**：

- 首批样板为教育、企业、文化类智能体。  
- 初期允许 Mock 模型与本地嵌入以保障可演示。  
- 子平台具备基本前端能力，可调用 REST。
